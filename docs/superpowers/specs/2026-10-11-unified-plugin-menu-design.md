# Isola 统一标题栏与插件菜单

页面使用一个宿主标题栏，插件切换、返回市场和当前插件业务操作在统一菜单完成。安装记录按用户和插件 `name` 唯一保存，SDK 通过绑定实际 iframe 的 MessageChannel 提供调用、订阅和菜单注册。

## 最小接口与实现

宿主只保留一个标题栏，显示菜单按钮、Isola 和当前页面名称。菜单提供市场入口、当前用户已安装的插件、当前插件的业务操作和退出登录。安装成功后，沿用安装结果按 `name` 注册或覆盖菜单入口；失败保持原入口。基础入口直接使用现有清单的 `name`、`isola.title` 和 `isola.entry`，不增加清单字段或服务端表。

SDK 0.1.1 提供业务菜单接口，使用绑定通道与 API 版本 1：

```ts
type PluginMenuItem = {
  id: string;
  label: string;
  disabled?: boolean;
  file?: { accept: string; multiple?: boolean };
  onSelect: (files: File[]) => void | Promise<void>;
};

client.registerMenu(items: PluginMenuItem[]): () => void;
```

每次注册替换该插件当前的业务菜单，返回函数只注销其对应的注册。普通操作收到空文件数组。文件操作由宿主菜单中的原生文件选择器取得用户选择，再用 MessageChannel 将 File 交给当前插件；取消不执行回调，再次选择同一文件仍可触发。回调异常显示错误，异步回调也要捕获。

注册消息只由当前实际 iframe 的绑定通道接收，宿主检查菜单条目的字段类型和重复标识。切换、断开及重新加载时清除旧菜单；旧注册的清理、选择和异步错误不能作用于新注册或另一个插件。保留原有 API 版本检查、沙盒、凭据隔离及请求和订阅的关闭逻辑。

宿主菜单使用原生 Popover 的退出和焦点行为。插件内容填满标题栏下方的空间，业务操作通过 `registerMenu` 注册。示例见[开发指南](../../plugin-development.md#3-写业务)和[官方笔记模板](../../../examples/notes/src/App.tsx)。

## 验收条件

- 已安装插件在登录和刷新后进入菜单；新安装和更新立即反映在同一入口，失败不增加入口。
- 在市场安装两个插件，通过菜单切换并返回市场；页面始终只有一个宿主标题栏。
- 业务操作确实调用当前插件；替换、注销、卸载 iframe、重连和伪造来源不留下或误调用旧菜单。
- 原生文件选择、取消和同一文件重试可用，插件收到原文件名和内容，错误反馈可见。
- 桌面和窄屏无宿主横向溢出，菜单键盘操作与 Escape 可用，原请求、File、表单和订阅行为不退化。
- 插件业务操作经过真实后端；升级前后比较两个测试账号的业务记录，原内容及各自归属保持一致。
