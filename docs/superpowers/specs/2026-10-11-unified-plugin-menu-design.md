# Isola 统一标题栏与插件菜单

用户已确认：页面只保留一个宿主标题栏，插件切换和返回市场在菜单完成；Grove 的菜单与“全图”也并入统一菜单。当前验收范围仍为 Web。

当前宿主分别渲染品牌账号栏和插件返回栏，Grove 0.1.4 另有导入资料、全部笔记和全图工具栏。安装记录已按用户和插件 `name` 唯一保存，SDK 已通过绑定实际 iframe 的 MessageChannel 提供调用和订阅。

## 最小接口与实现

宿主只保留一个标题栏，显示菜单按钮、Isola 和当前页面名称。菜单提供市场入口、当前用户已安装的插件、当前插件的业务操作和退出登录。用户名放在菜单内。安装成功后，沿用安装结果按 `name` 注册或覆盖菜单入口；失败保持原入口。基础入口直接使用现有清单的 `name`、`isola.title` 和 `isola.entry`，不增加清单字段或服务端表。

SDK 增加业务菜单接口，沿用现有通道与 API 版本 1；SDK 包更新为 0.1.1：

```ts
type PluginMenuItem = {
  id: string;
  label: string;
  disabled?: boolean;
  file?: { accept: string; multiple?: boolean };
  onSelect: (files: File[]) => void | Promise<void>;
};

client.registerMenu(items: PluginMenuItem[]): () => void;
```

每次注册替换该插件当前的业务菜单，返回函数只注销其对应的注册。普通操作收到空文件数组。文件操作由宿主菜单中的原生文件选择器取得用户选择，再用 MessageChannel 将 File 交给当前插件；取消不执行回调，再次选择同一文件仍可触发。回调异常显示错误，异步回调也要捕获。

注册消息只由当前实际 iframe 的绑定通道接收，宿主检查菜单条目的字段类型和重复标识。切换、断开及重新加载时清除旧菜单；旧注册的清理、选择和异步错误不能作用于新注册或另一个插件。保留原有 API 版本检查、沙盒、凭据隔离及请求和订阅的关闭逻辑。

宿主菜单使用原生 Popover 的退出和焦点行为。插件内容填满标题栏下方的空间。Grove 通过公开接口注册导入资料、全部笔记和全图，移除自身应用标题栏及对应旧 DOM 引用；编辑器、画板数据和业务接口保持原样。其插件版本与后端镜像同步更新为 0.1.5，通过现有市场覆盖安装。官方开发模板同时展示菜单注册，预览仍只保留 Grove。

## 验收条件

- 已安装插件在登录和刷新后进入菜单；新安装和更新立即反映在同一入口，失败不增加入口。
- 菜单可返回市场并在两个真实安装的测试插件间切换；Grove 接入后页面只有一个标题栏。
- 业务操作确实调用当前插件；替换、注销、卸载 iframe、重连和伪造来源不留下或误调用旧菜单。
- 原生文件选择、取消和同一文件重试可用，插件收到原文件名和内容，错误反馈可见。
- 桌面和窄屏无宿主横向溢出，菜单键盘操作与 Escape 可用，原请求、File、表单和订阅行为不退化。
- Grove 的全部笔记和全图可用，导入和保存仍经过真实后端；升级保留已有两位测试用户的数据。
